Core Web Networking & Browser Concepts

Gaining insight into the environment in which a web application runs requires examining six foundational concepts that govern how computers connect, locate resources, and display web pages.

1. Computer Networks, Routers, and TCP/IP

For two computers to exchange information across a network, they require both a physical or wireless link and a commonly understood protocol. On the Internet, the Transmission Control Protocol / Internet Protocol (TCP/IP) enables computers to exchange data packets and control acknowledgements so that information is transmitted reliably. Between a home computer and a web server, specialist computing devices called routers act like network traffic directors, handing data from one router to the next across commercial, educational, and government backbone networks until it reaches its destination.

2. IP Addresses and the Domain Name System (DNS)

Every device connected directly to the Internet requires a unique four-byte numerical identifier known as an Internet Protocol (IP) address, written in dotted decimal notation. Because numerical addresses are difficult for people to memorize, the Domain Name System (DNS) serves as a hierarchical, decentralized naming system that translates human-friendly domain names into numerical IP addresses, starting from root nameservers.

3. Domain Hierarchy and Top-Level Domains (TLDs)

A domain name is structured to tell users the general purpose of the service behind the address. While generic Top-Level Domains (TLDs) such as .com, .org, and .net do not enforce strict eligibility criteria, specialized TLDs maintain stricter policies: local TLDs like .us or .fr indicate a specific country or language, .gov is restricted to government departments, and .edu is reserved exclusively for educational and academic institutions.

4. Uniform Resource Locators (URLs) and Hyperlinks

A Uniform Resource Locator (URL) functions much like a postal mail address for the Web: the scheme (such as https) represents the postal service protocol, the domain name identifies the city or server location, the port acts like a zip code, the path specifies the building or file on the server, and an anchor points to a specific section inside a document. Embedded hyperlinks tie these URLs together, allowing users to navigate between pages and enabling search engines to crawl and index the Web.

5. Hypertext Transfer Protocol (HTTP & HTTPS)

Sitting on top of TCP/IP, HTTP is the human-readable application protocol that browsers and web servers use to talk to one another. Browsers use HTTP verbs such as GET to request a web page and POST to submit form data for processing, while the protocol also supports caching, filtering, load balancing, authentication, and logging. On the modern Web, servers rely on HTTPS, the secure version of HTTP that protects data in transit from interception.

6. Hypertext Markup Language (HTML) and Rendering

Inside the payload of an HTTP response sits HTML, a text-based markup language that uses nested angle-bracket tags and attributes (such as src, height, and width for images) to describe the structure of a document. When the browser receives an HTML file, it reads the markup instructions and converts the description into a visual screen display through a process called rendering.
